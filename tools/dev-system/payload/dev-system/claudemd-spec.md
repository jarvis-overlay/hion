# 프로젝트 CLAUDE.md 준비 기준 (개발부서 체계용)

`/dev`와 `/project-setup`이 공통으로 쓰는 기준. 에이전트들이 이 항목을 읽고 프로젝트에 맞게 움직인다.

## 필수 항목 (7개)
1. **프로젝트 설명**: 무엇을 하는 서비스인지 1~2줄
2. **실행 방법**: 로컬 실행 명령
3. **시험·검사 명령**: 시험/빌드/문법 검사 명령 + **실제 DB·외부 서비스(슬랙, 운영 서버 등)에 닿지 않게 돌리는 방법**. 안전한 방법이 없으면 "없음"이라고 명시
4. **금지 사항**: 건드리거나 커밋하면 안 되는 파일, 시크릿 위치와 취급, 운영 시스템 접근 규칙
5. **영역 지도**: 기능/영역 → 폴더·파일 (영역 담당 에이전트용)
6. **문서 규칙**: 어떤 변경을 하면 어떤 문서를 같이 고치는지
7. **브랜치·배포 규칙**: main 직접 푸시 허용 여부(허용이면 `.claude/dev-system.json`에 `{"allow_main_push": true}`), PR 방식, 배포 주체와 절차 문서 위치

## 작성 절차
1. **읽어서 채운다**: 저장소 구조, `package.json`/`requirements.txt`/`pyproject.toml`/`Makefile`/`docker-compose.yml`/`.github/workflows`/`README`/`.gitignore`/`.env.example`/기존 문서를 읽고, **코드에서 확인된 것만** 적는다.
2. **추측하지 않는다**: 확인 못 한 항목(특히 3 시험의 안전한 실행 방법, 4 운영 접근 규칙, 7 배포 절차)은 `(확인 필요)`로 남기고 사용자에게 한꺼번에 묻는다.
3. **기존 CLAUDE.md가 있으면 덮어쓰지 않는다**: 없는 항목만 추가하는 제안으로 보여 주고 승인받는다.
4. **초안을 보여 주고 승인받은 뒤에만 파일을 쓴다.** 시크릿 값은 절대 적지 않는다(이름/위치만).
5. 길이는 짧게(1~2쪽). 상세는 `docs/` 같은 기존 문서를 링크한다.

## 준비 상태 판정
- **충분**: CLAUDE.md가 있고 1~7 중 3(시험), 4(금지), 7(브랜치) 항목이 모두 있다 → 그대로 진행
- **부족**: CLAUDE.md는 있으나 3·4·7 중 빠진 것이 있다 → 빠진 항목만 보강 제안
- **없음**: CLAUDE.md 자체가 없다 → 전체 초안 작성
