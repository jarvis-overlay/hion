# 개인용 개발부서 체계 (Claude Code)

어떤 프로젝트에서든 **규모(S/M/L)에 맞춰 필요한 만큼만** 에이전트를 써서 개발하게 하는 개인용 설정이다. 목표는 **토큰 최소 + 품질 유지**.
모든 파일은 `~/.claude/` 아래에 있고, 프로젝트 저장소는 건드리지 않는다. (원본·수정은 hion 저장소 `tools/dev-system/`)

## 구성
| 종류 | 파일 | 역할 |
|---|---|---|
| 명령 | `commands/dev.md` | `/dev <요청>` — 오케스트레이터. 규모 판단 후 에이전트 호출 |
| 명령 | `commands/resume.md` | `/resume` — 세션 시작: 인수인계 파일 상단 + git·PR 상태 비교 |
| 명령 | `commands/handover.md` | `/handover` — 세션 종료: 점검, 커밋·푸시, 인수인계 파일을 **상세하게** 갱신 |
| 명령 | `commands/project-setup.md` | `/project-setup` — 프로젝트 `CLAUDE.md` 점검·초안 |
| 기준 | `dev-system/claudemd-spec.md` | CLAUDE.md 필수 항목 7개 |
| 훅 | `hooks/guard.py` (+ settings.json PreToolUse/Bash) | 강제 푸시, `--no-verify`, `git add -A/.`, 시크릿 스테이징 차단. main 푸시는 프로젝트 설정으로 허용/차단 |
| 시험 | `hooks/test_guard.py` | 가드 시험 |

| 에이전트 | 역할 | 모델 |
|---|---|---|
| `dev-planner` | 기획+설계(완료 기준·영향 범위·위험·시험 계획·규모) | sonnet |
| `dev-implementer` | 구현(커밋 안 함) | 세션 모델 |
| `dev-reviewer` | 독립 리뷰 + 타입 검사/시험 실행 | sonnet |
| `dev-verifier` | 교차 검증(높음 지적 하나를 재현/반박) | **opus** |

## 흐름
| 규모 | 기준 | 흐름 |
|---|---|---|
| S | 한 파일/한 동작, 문구·단순 버그 | 직접 수정 → 직접 타입 검사 (에이전트 없음) |
| M | 여러 파일 일반 기능 | planner → implementer → reviewer → 지적 있으면 1회 수정 |
| L | 스키마·권한·결제·AI 생성 로직·외부 시스템·배포 | M + 계획 승인 + 높음 지적은 verifier |

## 설계 원칙
1. **결정적 검증 우선**: 타입 검사·시험·가드 훅은 토큰이 거의 안 든다. 에이전트 검증은 보강.
2. **독립성**: 리뷰어는 구현자 설명을 못 본다(diff와 완료 기준만).
3. **증거 기준**: 지적은 `파일:줄` + 시나리오 + 근거. 재현되는 쪽이 이긴다.
4. **교차 검증 익명성**: verifier에게 출처·심각도를 숨긴다.
5. **강제할 것은 훅으로**.
6. **토큰 절약**: opus는 교차 검증만, 수정 최대 1라운드, 재검증은 고친 diff만, 범위 밖 발견은 백로그.
7. **정직한 보고**: "직접 확인한 것 / 확인하지 못한 것"을 항상 나눈다.

## 프로젝트별 설정
프로젝트 `.claude/dev-system.json`: `{"allow_main_push": true, "prod_hosts": []}` (없으면 가장 엄격한 기본값 = main 푸시 차단).

## 한계
- `/dev`는 모델이 따르는 절차다. 단계를 건너뛴 것 같으면 에이전트 호출 내역을 확인한다.
- 같은 모델끼리라 맹점을 공유할 수 있다 → 시험 실행·재현을 요구한다.
- 가드 훅은 Bash 명령 문자열만 해석하는 안전망이다(보안 경계가 아님).
