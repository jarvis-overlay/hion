description: 세션을 마무리한다 — 변경 확인, 시크릿 점검, 커밋·푸시, 인수인계 파일 갱신
---

현재 세션을 마무리하고 다음 세션(다른 사람 포함)이 바로 이어갈 수 있게 인수인계한다. **인수인계 파일은 이 프로젝트에서 상세 기록장이다** — 요약만 남기지 말고 다음 세션이 필요한 맥락을 자급자족하게 적는다.

## 진행 순서

### 1. 현재 상태 파악 (병렬)
- `git status -s`, `git branch --show-current`, `git log --oneline -10`
- 현재 todo 목록
- `인수인계 파일` 존재 여부, 프로젝트 `CLAUDE.md`의 협업/문서 규칙

### 2. 점검 — 하나라도 걸리면 멈추고 사용자에게 알린다
- 현재 브랜치가 `main`/`master`: 프로젝트 `CLAUDE.md`·`.claude/dev-system.json`이 main 직접 푸시를 허용하면 진행한다. 허용하지 않으면 **커밋하지 않고** 작업 브랜치를 새로 만들지 묻는다.
- **큰·위험한 변경**(AI 생성 로직, 결제·인증 등)을 main에 바로 푸시하려는 것이면 `CLAUDE.md`의 규칙(feature 브랜치 + Preview 확인)을 상기시키고 확인받는다.
- 변경에 시크릿 후보가 있다: `.env`, `*credential*`, `*serviceAccount*`, `*.pem`, `config.json`, `*.db`, 토큰/키 패턴(`xox[bp]-`, `AIza`, `-----BEGIN`, `ghp_`) → 스테이징 금지, 목록만 보여 준다.
- 프로젝트 `CLAUDE.md`가 "변경 시 같이 고쳐야 할 문서"를 정해 뒀다면, 이번 변경에 대응하는 문서 갱신이 빠졌는지 확인하고 알린다.

### 3. 세션 요약 도출
사용자 메시지와 도구 호출을 기반으로 시간순으로:
- **완료** / **부분 완료** / **차단됨** / **발견된 이슈·기술 부채**
- **확인하지 못한 것**(실제 외부 시스템 미검증 등)은 반드시 따로 적는다 — 다음 사람이 이걸 모르고 "끝난 일"로 착각하면 사고가 난다.

### 4. 미커밋 변경 처리
- 변경을 **논리 단위**로 묶어 커밋한다. 스테이징은 **구체적인 파일명**으로(`git add -A`, `git add .` 금지).
- 커밋 메시지는 프로젝트 관례를 따른다(`git log`로 확인). 프로젝트/시스템이 정한 공동 작성자 줄이 있으면 붙인다.
- 푸시: **푸시가 곧 배포인 프로젝트면 푸시 전에 사용자에게 한 번 확인**한다(무엇이 배포되는지 한 줄). 푸시 전 `git pull`(여러 PC 작업 대비). `--no-verify`·강제 푸시 금지.
- **PR**: 만들지 여부와 대상 브랜치를 사용자에게 확인한다(확인 없이 만들지 않는다). 만들 때는 본문에 변경 요약, 배포 영향(스키마/설정 키/재시작/별도 배포 대상), 검증 근거, **확인하지 못한 것**을 쓴다.

### 5. 인수인계 파일 갱신 (`HANDOFF.md` 우선, 없으면 `HANDOVER.md`, 둘 다 없으면 아래 템플릿으로 `HANDOFF.md` 생성)
**상세하게 쓴다 — 다음 세션이 이 대화를 못 본다는 전제로, 어느 PC·어느 창에서든 바로 이어갈 수 있게.** 이력을 줄이거나 지우지 않는다. 맨 위 "지금 상태·남은 일"은 항상 최신으로 고치고(여기만 읽어도 이어갈 수 있게), 상세 기록은 아래 섹션에 쌓는다. 반드시 포함: 확인한 것 / **확인하지 못한 것(실제 외부 API·운영 화면)** / 사용자 확인 대기 항목 / 미실행 SQL·마이그레이션 / 관련 파일·커밋 해시.
- **마지막 업데이트**: 날짜 + 세션 핵심 한 줄
- **이번 세션 작업 요약**: 새 내용으로 교체. 직전 세션 요약은 "직전 세션"으로 한 단계 내리고, 3세션 이상 지난 것은 삭제(git 히스토리가 보존)
- **다음 세션 최우선 할 일**: 재작성. **"다음 세션은 이 대화를 못 본다"** 는 전제로, 파일 경로·커밋 해시·배경을 자급자족하게
- **백로그**: 새 항목 추가, 완료 항목은 `[x]` 처리(다음 세션에 삭제). 20개를 넘으면 우선순위 재검토를 제안
- **알려진 이슈**, **환경 정보** 변경분 반영
- 인수인계 파일 변경도 같은 커밋(또는 마지막 커밋)에 포함한다.

인수인계 파일 템플릿:
```
# HANDOFF

**마지막 업데이트**: YYYY-MM-DD — 한 줄 요약
**브랜치/PR**: …

## 이번 세션 작업 요약
- 완료: …
- 부분 완료: …
- 차단됨: …
- 확인하지 못한 것: …

## 직전 세션
- …

## 다음 세션 최우선 할 일
1. … (관련 파일: …, 배경: …)

## 백로그
- [ ] …

## 알려진 이슈
- …

## 환경 정보
- …
```

### 6. Todo 정리
완료한 것은 completed, "다음 세션 최우선 할 일"은 todo로 남긴다.

### 7. 최종 리포트
```
## 인수인계 완료
**커밋**: {개수, 해시}   **푸시**: {브랜치}   **PR**: {번호/없음/확인 대기}
**인수인계 파일**: 갱신됨
### 이번 세션 핵심 (3~5줄)
### 확인하지 못한 것
### 다음 세션 1순위 (1~2줄)
```

## 주의
- 사용자 승인 없이 PR 생성·머지·배포를 하지 않는다.
- 다른 사람이 쓴 인수인계 파일 내용을 지우지 않는다. 충돌 시 "다음 세션 최우선 할 일"은 양쪽의 합집합, "작업 요약"은 양쪽 내용 보존.
