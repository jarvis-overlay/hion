이전 세션이 남긴 인수인계를 읽고, 저장소의 **지금 상태**와 비교해서 작업을 이어갈 준비를 한다. 이 명령은 **읽기와 보고만** 한다(파일 수정·커밋 없음).

## 진행 순서

### 1. 병렬로 읽기
- 프로젝트에 `tools/dev-system/install.py`가 있으면 `python tools/dev-system/install.py --check` 실행. 설치본이 키트와 다르면 리포트 맨 위에 알리고, 승인받아 `python tools/dev-system/install.py`로 갱신(갱신 뒤엔 새 세션 필요)한다.
- 프로젝트 루트 인수인계 파일: `HANDOFF.md`(없으면 `HANDOVER.md`). **파일이 길면 맨 위 "지금 상태·남은 일" 부분과 거기서 가리키는 섹션만 읽는다**(과거 이력 전체를 읽지 않는다 — 토큰 절약). 더 필요할 때만 해당 섹션을 추가로 읽는다.
- 이 PC가 여러 대 중 하나라면 `git pull` 먼저(다른 PC의 작업 반영)
- 프로젝트 `CLAUDE.md`의 "세션 시작 규칙"/협업 규칙 (있으면 그대로 따른다)
- `git branch --show-current`, `git status -s`, `git log --oneline -8`
- `git fetch --quiet` 후 `git rev-list --left-right --count HEAD...origin/main` (뒤처짐/앞섬)
- `gh pr list --state open --limit 10` (gh가 있고 인증돼 있을 때만, 실패하면 건너뜀)

### 2. 상태 비교
인수인계 파일의 마지막 갱신 이후의 변화를 찾는다.
- 새 커밋(다른 사람/세션): 메시지를 요약해 보여 준다
- 미커밋 변경: 파일 목록만 알린다(자동 처리하지 않는다)
- 현재 브랜치가 `main`/`master`이면: `CLAUDE.md`가 main 직접 작업을 허용하면 그대로, 아니면 작업 브랜치를 따야 한다고 알린다
- `origin/main`이 앞서 있으면: `git pull` 필요 여부를 알린다
- 열린 PR: 번호/제목/브랜치만 보여 준다

### 3. 컨텍스트 사전 로드
"남은 일" 1순위가 가리키는 파일을 **최대 3개**까지 읽는다. 경로 표시가 없으면 건너뛴다.

### 4. Todo 등록
"남은 일" 항목을 todo로 등록한다. 첫 항목을 자동으로 시작하지 않는다.

### 5. 리포트
```
## 이전 세션 인수인계
**마지막 업데이트**: {날짜} — {한 줄}
**브랜치**: {현재} (origin/main 대비 앞 {a} / 뒤 {b})  |  미커밋: {N개 or 없음}

### 사용자 확인 대기 / 확인 못 한 것
### 1순위
{내용, 관련 파일}
### 2~3순위
### 백로그 ({N}개, 최대 5개 표시)
### 알려진 이슈
### ⚠️ 변경 감지  (있을 때만)
### 열린 PR  (있을 때만)

---
1순위부터 시작할까요? 규모가 있는 작업이면 `/dev <내용>`으로 개발부서 체계로 진행할 수 있어요.
```

### 6. 응답 대기
"시작"/"1순위" → 해당 todo를 in_progress로 바꾸고 시작. 그 외 지시는 그대로 따른다.

## 인수인계 파일이 없을 때
중단하지 말고 `docs/README.md`, `CLAUDE.md`, 최근 커밋·열린 PR로 같은 리포트를 만든다. "세션을 마칠 때 /handover가 만들어 줘요"라고 안내한다.

## 주의
- 인수인계 파일을 수정하지 않는다(`/handover`의 몫).
- 미커밋 변경과 브랜치 상태를 사용자 허락 없이 바꾸지 않는다.
